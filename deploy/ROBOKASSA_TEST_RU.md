# GoStudy: Robokassa, этап 1 — тестовая оплата

Только тестовые платежи. Реальные списания, автопродление, кассовые чеки, возвраты и платные ограничения этим патчем НЕ включаются. Тестовый период хранится отдельно и не предоставляет платный доступ. Проверка доступна только ID преподавателей из ROBOKASSA_TEST_TEACHER_IDS.

## Что реализовано
- Сумма и лимиты из опубликованного тарифа; версия и условия сохраняются в заказе.
- Базовый период строго 30 дней; блоки учеников считаются на сервере.
- Переход формой POST в тестовую среду Robokassa, IsTest=1 без Recurring.
- ResultURL проверяет подпись паролем №2, точную сумму и счёт. Параллельные уведомления сериализуются в PostgreSQL. Повторное уведомление не добавляет период.
- Success/Fail только возвращают в кабинет. История показывает статус из базы.
- Заказы/тестовые периоды не затрагивают уроки, комиссии и выплаты.

## Установка исходников
Windows: распаковать ZIP в E:\Project\gostudy с заменой файлов. На сервере распаковать ZIP в отдельный временный каталог и выполнить от root:
`python3 /путь/к/распакованному/патчу/deploy/install-robokassa-test-patch.py /srv/gostudy/app`
Установщик сверяет исходные файлы с предоставленным архивом и прекращает установку при несовпадении; делает резервную копию, не меняет .env, package.json/lock, uploads и настройки Nginx.

## Проверки
В корне: `npm run lint`, `npm run build`, `npm run server:lint`, `npm run server:test`, `npm --prefix server run test:modules`.
Перед первой миграцией на сервере сохранить резервную копию БД. Применить `npm --prefix server run prisma:migrate:deploy` с DATABASE_URL из /etc/gostudy/database.env. Для Prisma generate использовать `npm run server:prisma:generate`. После миграции/сборки — штатная публикация dist и перезапуск gostudy-api. Старые хешированные assets при публикации сохранять.

## Настройки (вносить приватно; секреты в чат не присылать)
В /etc/gostudy/app.env добавить:
ROBOKASSA_TEST_ENABLED=true
ROBOKASSA_MERCHANT_LOGIN=gostudy
ROBOKASSA_TEST_TEACHER_IDS=ID_ТЕСТОВОГО_ПРЕПОДАВАТЕЛЯ
ROBOKASSA_TEST_PASSWORD1=отдельный тестовый пароль №1
ROBOKASSA_TEST_PASSWORD2=отдельный тестовый пароль №2

Используются ТОЛЬКО тестовые пароли из кабинета Robokassa, разные между собой. Файл загружается systemd; не выполнять source app.env. Права root:gostudy 640. Рабочие пароли не нужны.
В технических настройках Robokassa алгоритм MD5:
ResultURL: https://gostudyonline.ru/api/v1/payments/robokassa/result (POST)
SuccessURL: https://gostudyonline.ru/api/v1/payments/robokassa/success (GET)
FailURL: https://gostudyonline.ru/api/v1/payments/robokassa/fail (GET)

## Проверка на сайте
Войти тестовым преподавателем → Подписка → Проверка оплаты. Подтвердить тестовый режим и перейти в Robokassa. Не вводить настоящие данные карты для теста; пользоваться действиями тестового интерфейса. После возврата обновить статус: запись должна быть «Подтверждён сервером». При отмене период не появляется. Повторный callback с тем же счётом не меняет окончание периода.

## Следующий этап
До реального приёма оплат необходимо выбрать сервис фискализации и подтвердить налоговую систему/НДС с владельцем ИП. Затем реализовать реальные заказы, чеки и их статусы, согласие на периодические списания с фиксацией редакции документов, автопродление и отмену, уведомление об изменении цены, доплаты/уменьшение блоков и возвраты. На сайте до этого не включать платные ограничения. В данном патче отсутствует путь к реальному списанию — смены одного флага недостаточно.
