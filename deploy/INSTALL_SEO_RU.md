# Единое обновление SEO и контактов GoStudy

Архив включает телефон из предыдущего патча. Ставить оба архива не нужно.
Предполагается актуальный GoStudy с уже установленным патчем подписки на 30 дней от 8 октября.

## На компьютере

Распакуйте архив в `E:\Project\gostudy` с заменой файлов. В этой папке выполните:

```powershell
npm run lint
npm run build
npm run server:lint
npm run server:test
npm --prefix server run test:modules
node server/scripts/check-public-pages-http.cjs
```

Сборка фронтенда теперь также создаёт `server/public-pages-renderer`.
Это отдельный серверный renderer страницы тарифа, не папка для загрузки в публичный каталог.
Новые зависимости, `npm install`, миграции и повторное заполнение БД не требуются.

## На сервере

Загрузите этот же ZIP в `/tmp/` и распакуйте в `/srv/gostudy/app` с заменой файлов:

```bash
unzip -o /tmp/gostudy_patch_2026-10-23_seo-and-contacts.zip -d /srv/gostudy/app
bash /srv/gostudy/app/deploy/apply-seo-update.sh
```

Запускайте от пользователя `ubuntu`, не из root. Будет запрошен пароль sudo, если он требуется.
Установщик проверяет проект, сохраняет предыдущие сборки и конфигурацию nginx в
`/var/backups/gostudy/seo-...`, собирает фронтенд и API, проверяет граф модулей,
перезапускает API, публикует статику с группой `www-data`, точечно обновляет маршруты nginx,
выполняет `nginx -t` и проверяет публичные страницы через локальный HTTPS.

При ошибке после создания резервной копии установщик пытается восстановить предыдущие
сборки, статику и конфигурацию nginx. Если конфигурация сервера отличается от ожидаемой,
он останавливается, не заменяя незнакомые настройки. Сохраните текст ошибки и сообщите его.

База данных, её пользователи, тарифные публикации, загрузки, `.env`, настройки SMTP,
TLS-сертификаты и зависимости npm не изменяются. Сбора платежей этот патч не включает.
Цена читается из опубликованного тарифа в существующей БД на каждый запрос `/pricing`.

Отдельная проверка после выкладки:

```bash
cd /srv/gostudy/app
node scripts/check-seo-deployment.mjs --local
```

В текущей среде разработки проверены сборки, тесты и HTTP-ответы нового модуля без подключения
к рабочей БД. Нативная проверка nginx выполняется только установщиком на сервере.
Мобильный и десктопный внешний вид следует проверить после установки: предпросмотр в
удалённом браузере во время подготовки патча был недоступен.
