# GoStudy — админка «Подписки и оплаты»

Пакет от 02.11.2026. Подготовлен на архиве `gostudy-main (2)(5).zip`
с патчами `robokassa-live-pilot` и `classroom-video` от 01.11.2026.

## Что добавлено

- Пункт «Подписки и оплаты» в админке, адрес `/admin/subscriptions`.
- Чтение доступно только роли ADMIN. Модератор, преподаватель, родитель и ученик получают отказ.
- Одна строка на заказ: преподаватель (ФИО, email, ID), ID заказа, сумма, статус,
  создание и оплата, начало и конец оплаченного периода, лимит учеников,
  количество дополнительных блоков, статус задания итогового чека.
- Поиск по имени, email, ID преподавателя или заказа; фильтры по реальным/тестовым
  платежам, оплате, состоянию периода, итоговому чеку и датам оплаты.
- По умолчанию только реальные платежи. Тестовые суммы явно помечены и не называются выручкой.
- Даты отображаются по Москве. Верхняя граница фильтра оплаты включает весь выбранный день.
- Сумма оплаченных заказов до вычета комиссий и счётчики считаются по всем строкам,
  подходящим под применённые фильтры, а не только по текущей странице.
- Пагинация, состояния загрузки/ошибки/пустого результата, светлая и тёмная темы.
- Для итогового чека доступны срок, отправка, регистрация, число попыток,
  следующая проверка, последний код и причина приостановки.

## Границы

Это журнал для просмотра. Изменение оплаты или периода, ручное создание платежей,
возвраты и отправка/приостановка чеков в новом экране не добавлены.
Новый GET API не выполняет запросы в Robokassa и не изменяет базу.
Существующий обработчик подтверждений и worker чеков не изменяются.
Миграции БД, смена паролей и флагов реальных платежей для этого пакета не нужны.

Первый кассовый чек не имеет сохранённого проверенного статуса в текущей модели:
в колонке показано «Проверить в Robokassa», а не «Зарегистрирован» на основании оплаты.
Автоматическое получение/хранение статуса первого чека остаётся отдельной задачей.
Тестовые периоды старой модели `SubscriptionTrial` учитываются отдельно и не выдаются за реальные периоды.
Уже созданные неоплаченные счета сохраняются со статусом «Ожидает оплаты».

## Установка исходников

1. Распаковать этот архив в отдельную папку, не поверх проекта.
2. Установить исходники через `deploy/install-admin-subscriptions-patch.mjs`.
   Он проверяет все файлы до записи, останавливается при несовпадении,
   создаёт резервную копию и поддерживает повторный запуск без лишних изменений.
3. Если установщик сообщает о несовпадении файла, остановиться и сверить текущие исходники.
   Это может означать, что один из предыдущих патчей не установлен или файл изменён позднее.
   Не обходить проверку принудительной распаковкой поверх проекта.

Локально, из распакованного пакета:

```powershell
node .\deploy\install-admin-subscriptions-patch.mjs "E:\Project\gostudy"
```

На VPS, из распакованного пакета:

```bash
sudo node ./deploy/install-admin-subscriptions-patch.mjs /srv/gostudy/app
```

Установщик меняет только файлы из `deploy/admin-subscriptions-patch.json`.
Он не изменяет `.env`, сервисы, nginx, базу, загрузки или зависимости.

## Проверки и публикация

Выполнять по одной команде из корня проекта, проверяя результат каждой:

```bash
npm run server:prisma:generate
npm run server:lint
npm run server:test
npm --prefix server run test:modules
node server/scripts/check-admin-subscriptions-http.cjs
npm run lint
npm run build
```

HTTP-проверка запускает временный локальный сервер с заглушкой БД и сессий.
Она проверяет реальный NestJS guard/маршрут/валидацию/заголовок no-store,
не использует production базу, пароли или платёжный сервис.

После успешных проверок на VPS:

```bash
sudo rsync -a --chown=ubuntu:www-data --chmod=D2750,F640 /srv/gostudy/app/dist/ /var/www/gostudy/
sudo systemctl restart gostudy-api
curl -fsS --max-time 10 http://127.0.0.1:3002/api/v1/health
```

Не добавлять `--delete` к rsync: открытым вкладкам могут понадобиться старые ресурсы.
Для этого пакета не запускать новую миграцию или `db push`.

## Проверка на сайте

1. Войти именно в административный кабинет под ADMIN.
2. Открыть «Подписки и оплаты»; режим по умолчанию — «Реальные».
3. Контрольная покупка: заказ №3, преподаватель ID 3, 990 ₽, «Оплачен»,
   период 02.11.2026 18:03:46 — 02.12.2026 18:03:46 МСК, до 2 учеников.
   Более ранний заказ №2 остаётся неоплаченным, без оплаченного периода.
4. Проверить фильтры, поиск, «Данные чека» и переход в карточку преподавателя.
5. У MODERATOR пункт отсутствует; прямой переход не раскрывает данные,
   API возвращает 403. Без сессии API возвращает 401.

В этой среде реальные данные VPS не запрашивались. Публикация и проверка заказа №3
на установленном новом экране выполняются отдельно.
