# GoStudy — привязка существующего аккаунта ученика к родителю

Дата: 8 сентября 2026 года.

## Граница этапа

Подтверждённая администратором карточка ребёнка связывается с уже
зарегистрированным аккаунтом ученика. Новый пользователь не создаётся, пароль,
анкета, преподаватели, расписание, задания, материалы и сообщения ученика не
изменяются.

Создание нового ученического аккаунта из кабинета родителя вынесено в отдельный
этап и описано в `PARENT_STUDENT_ACCOUNT_API_NODE.md`.

## Сценарий

1. Родитель открывает подтверждённую карточку и указывает email ученика.
2. Сервер проверяет роль `STUDENT`, активность аккаунта, подтверждённый email,
   совпадение имени, фамилии и года рождения с карточкой.
3. В кабинете ученика «Родитель» появляется запрос сроком на 7 дней.
4. Ученик подтверждает или отклоняет связь.
5. При подтверждении сервер транзакционно заполняет
   `parent_child_profiles.student_id` и создаёт активную подтверждённую запись
   `parent_students`.
6. Обе стороны получают внутренние уведомления.

Ответ при отсутствии аккаунта и при несовпадении данных одинаковый, чтобы API
не раскрывал постороннему человеку сведения о регистрации конкретного email.

## Маршруты

Для родителя:

- `POST /api/v1/parent/children/:id/link-existing` — отправить запрос;
- `GET /api/v1/parent/children` — получить карточку и последнее состояние
  запроса.

Тело запроса:

```json
{
  "email": "student@example.com"
}
```

Для ученика:

- `GET /api/v1/student/parent-link-requests` — ожидающие запросы и уже
  подтверждённые представители;
- `POST /api/v1/student/parent-link-requests/:id/respond` — принять или
  отклонить запрос.

```json
{
  "accept": true
}
```

## Ограничения

- запрос отправляет только владелец карточки с ролью `PARENT`;
- карточка должна иметь статус `VERIFIED`;
- один ученический аккаунт нельзя привязать к другой активной карточке;
- одновременно у карточки может быть только один ожидающий запрос;
- просроченные запросы автоматически получают статус `EXPIRED`;
- окончательная связь создаётся только после ответа авторизованного ученика.

## База данных

Миграция `20260908203000_parent_student_link_requests` создаёт историю запросов
и частичный уникальный индекс для одного ожидающего запроса на карточку.

После установки файлов в каталоге `server` выполнить:

```bash
npx prisma migrate deploy
npx prisma generate
```

Затем пересобрать и перезапустить API и frontend.

## Состояние

Привязка существующего аккаунта реализована. Для неё по-прежнему обязательно
подтверждение самим учеником; автоматическая связь применяется только при
создании нового аккаунта родителем из уже проверенной карточки.
