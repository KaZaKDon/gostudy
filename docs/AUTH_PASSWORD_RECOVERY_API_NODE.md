# GoStudy — восстановление пароля на NestJS/PostgreSQL

**Дата:** 8 сентября 2026 года  
**Статус:** реализовано и проверено

## Архитектура

Восстановление пароля вынесено в отдельный `PasswordRecoveryService` внутри
модуля `auth`. Оно не смешивается со сменой пароля авторизованного пользователя
в `SecurityService`.

Новая миграция не требуется: используется существующая таблица
`password_reset_tokens`.

## Маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/v1/auth/forgot-password` | запросить письмо восстановления |
| `POST` | `/api/v1/auth/reset-password` | установить новый пароль по токену |

### Запрос письма

```json
{
  "email": "student@example.com"
}
```

Ответ одинаков для существующего и неизвестного email, поэтому маршрут не
позволяет проверять наличие аккаунтов. Повторное письмо можно запросить через
60 секунд.

Создаётся случайный одноразовый токен. В базе хранится только его SHA-256-хеш.
Ссылка имеет вид `/password-reset?token=...` и по умолчанию действует 60 минут.

### Установка нового пароля

```json
{
  "token": "токен из ссылки",
  "new_password": "новый пароль",
  "new_password_confirmation": "новый пароль"
}
```

Пароль должен содержать не менее 8 символов, занимать не более 72 байт UTF-8,
совпадать с подтверждением и отличаться от текущего. После успешной операции:

- использованный токен и все остальные активные токены пользователя
  становятся недействительными;
- новый пароль сохраняется через bcrypt;
- все ранее открытые сеансы пользователя завершаются.

Для отсутствующего, просроченного и уже использованного токена клиент получает
единое сообщение: «Ссылка восстановления недействительна, истекла или уже была
использована». Оно не вводит пользователя в заблуждение и не раскрывает причину
отказа постороннему.

## Настройки окружения

```text
PASSWORD_RESET_MINUTES=60
PASSWORD_RESET_RESEND_SECONDS=60
```

Письма отправляются существующим `MailService`. В development-режиме без SMTP
ссылка выводится в журнал Node API.
