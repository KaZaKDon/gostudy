# GoStudy — сообщения на NestJS/PostgreSQL

**Дата:** 3 сентября 2026 года  
**Статус:** реализовано

## Назначение

Модуль обеспечивает личную переписку в рамках подтверждённой учебной связи:

- преподаватель ↔ ученик;
- преподаватель ↔ подтверждённый аккаунт родителя.

Ученик не может переключиться в режим родителя и отправить сообщение от его
имени. Родительский канал доступен только пользователю с ролью `PARENT`,
который связан с ребёнком записью `parent_students` с заполненным
`verified_at`. Создание и подтверждение родительских аккаунтов будет завершено
в отдельном модуле; текущая схема сообщений уже не потребует переделки.

## Пользовательские маршруты

Все маршруты требуют действующий `X-Auth-Token` или Bearer-токен.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/messages/dialogs` | доступные диалоги и общий счётчик непрочитанных |
| `GET` | `/api/v1/messages/thread` | страница сообщений выбранного диалога |
| `POST` | `/api/v1/messages/send` | текст и/или до пяти файлов, multipart |
| `POST` | `/api/v1/messages/read` | отметить входящие сообщения диалога прочитанными |
| `POST` | `/api/v1/messages/report` | пожаловаться на чужое сообщение |
| `GET` | `/api/v1/messages/download` | защищённое скачивание вложения |

Диалог идентифицируется набором `teacher_id`, `student_id`, `channel_type` и,
для родительского канала, `parent_id`. Сервер каждый раз проверяет роль,
участников и учебную связь, поэтому подмена ID в браузере не предоставляет
доступ к чужой переписке.

## Правила переписки

- Новые сообщения разрешены только при активной связи преподавателя и ученика.
- После архивации связи история остаётся доступна обеим сторонам только для
  чтения.
- Родительский канал дополнительно требует активной подтверждённой связи
  родителя с ребёнком.
- Можно отправить текст, файлы либо оба варианта одновременно.
- Максимальная длина текста — 10 000 символов.
- Непрочитанными считаются только входящие, не скрытые администрацией
  сообщения.
- Получатель получает внутреннее уведомление, связанное с ID диалога.
- На первом этапе список опрашивается раз в 10 секунд, открытая переписка — раз
  в 5 секунд. WebSocket будет добавлен позднее без изменения API-модели.

## Файлы

Вложения хранятся в закрытом `UPLOAD_PRIVATE_DIR/messages`, не выдаются Nginx
как статические файлы и скачиваются только через авторизованный маршрут.
Применяются единые проверки расширения, MIME, сигнатуры и Unicode-названия.

Лимиты задаются переменными:

```env
UPLOAD_MESSAGE_MAX_BYTES=10485760
UPLOAD_MESSAGE_TOTAL_MAX_BYTES=31457280
```

По умолчанию разрешено до пяти файлов, до 10 МБ каждый и до 30 МБ за одно
сообщение. Секретный каталог на VPS должен находиться вне публичного корня.

## Жалобы и административный доступ

Административная панель не предоставляет свободный просмотр всех личных
диалогов. На `/admin/messages` выводятся только жалобы пользователей.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/admin/messages/reports` | очередь жалоб |
| `GET` | `/api/v1/admin/messages/reports/:id` | обжалованное сообщение и до пяти соседних с каждой стороны |
| `PATCH` | `/api/v1/admin/messages/reports/:id` | подтвердить или отклонить жалобу, при необходимости скрыть сообщение |
| `GET` | `/api/v1/admin/messages/reports/:id/download` | вложение именно обжалованного сообщения |

Каждое открытие контекста записывается в `admin_audit_logs` вместе с
администратором, IP и User-Agent. Скрытие возможно только при подтверждении
жалобы и требует причины. Скрытые текст и вложения перестают выдаваться
участникам диалога, сама запись сохраняется для аудита.

## PostgreSQL

Миграция `20260903220000_messages` создаёт:

- `parent_students`;
- `message_dialogs`;
- `messages`;
- `message_attachments`;
- `message_reports`;
- связанные enum, индексы, внешние ключи и ограничение типа канала.

Миграция не удаляет существующие аккаунты, уроки, задания или материалы.

## Проверка после установки

1. Ученик открывает «Сообщения», выбирает принятого преподавателя и отправляет
   текст и файл.
2. У преподавателя появляется счётчик в меню и уведомление в колокольчике.
3. Преподаватель открывает диалог, скачивает файл и отвечает.
4. Ученик отправляет жалобу на входящее сообщение.
5. Администратор открывает `/admin/messages`, проверяет ограниченный контекст и
   сохраняет решение.
6. После архивации учебной связи диалог остаётся видимым, но форма отправки
   заменяется режимом чтения.
