# GoStudy — расписание в Node API

**Дата:** 1 сентября 2026 года  
**Статус:** чтение, назначение, перенос, отмена и проведение урока реализованы

## Реализовано

- PostgreSQL-модели `lessons`, `lesson_sessions` и
  `lesson_change_requests`;
- хранение времени урока как `timestamptz`;
- защищённый маршрут
  `GET /api/v1/lessons/schedule?from=YYYY-MM-DD&to=YYYY-MM-DD`;
- выбор расписания только текущего ученика или преподавателя;
- период не более 32 календарных дней;
- преобразование границ периода и ответа в часовой пояс анкеты;
- сведения о предмете, втором участнике, состоянии онлайн-класса и последнем
  запросе на изменение;
- подключение React-кабинета к Node API.
- модель активной связи `teacher_students`;
- `GET /api/v1/lessons/options` со списком активных учеников и разрешённых
  продолжительностей;
- `POST /api/v1/lessons` для назначения урока преподавателем;
- серверная проверка цены выбранной продолжительности, будущей даты, предела в
  один год и пересечений в расписании преподавателя или ученика.
- уведомление ученика о новом уроке с переходом на его дату в расписании.
- предложение переноса или отмены любым участником будущего урока;
- принятие или отклонение предложения второй стороной;
- отзыв ожидающего предложения его автором;
- уведомления второй стороне о каждом действии.

Если часовой пояс анкеты пуст или некорректен, используется
`Europe/Moscow`.

## Онлайн-класс

Вход в класс и завершение занятия подключены к Node API. Вход открывается за
15 минут до начала. После того как преподаватель завершает начатый урок,
`lessons.status` становится `COMPLETED`, а ученику открывается возможность
оставить отзыв. Полный контракт описан в
[`CLASSROOM_API_NODE.md`](CLASSROOM_API_NODE.md).

## Изменение урока

```text
POST /api/v1/lessons/change-requests
POST /api/v1/lessons/change-requests/respond
POST /api/v1/lessons/change-requests/withdraw
```

Перенос или отмена не применяются в момент отправки предложения. Изменение
вступает в силу только после согласия второго участника. До ответа автор может
отозвать предложение. Отклонение требует комментария с причиной.

После подтверждения отмены карточка урока исчезает из действующего расписания
у ученика и преподавателя. Запись физически не удаляется: она остаётся в
PostgreSQL со статусом `cancelled` для истории, споров и будущих расчётов.
Пустой день обозначается нейтрально как «Нет уроков», а не как «Выходной».

Изменять можно только будущий урок со статусом `scheduled` или `rescheduled`,
если онлайн-класс ещё не начат и не завершён. Для одного урока одновременно
может существовать только одно ожидающее предложение. При подтверждении
переноса сервер повторно проверяет дату и пересечения обоих участников.

Активная связь создаётся автоматически, когда преподаватель принимает заявку
ученика. Пока активных связей нет, форма назначения урока корректно сообщает:
«Нет активных учеников».

## Применение миграции

После обновления проекта выполнить в корне:

```powershell
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
```

Миграции `20260831133000_schedule_foundation` и
`20260831150000_lesson_creation`, а также
`20260831170000_teacher_requests` и
`20260901143000_notifications` добавляют только новые таблицы и типы.
Существующие пользователи, анкеты и сеансы не удаляются.

Для включения переноса и отмены новая миграция не требуется: таблица
`lesson_change_requests` уже была создана миграцией основы расписания.

Миграция `20260902213000_classroom` расширяет сессию урока и добавляет чат,
материалы, общий показ и черновик заметки преподавателя.
