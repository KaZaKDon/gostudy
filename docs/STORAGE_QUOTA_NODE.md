# Единая квота пользовательского хранилища

Дата: 24 сентября 2026 года.

## Назначение

`StorageQuotaModule` ограничивает суммарный объём приватных файлов одного
аккаунта. Ограничение действует одинаково для преподавателя, ученика и
родителя и не зависит от того, через какой раздел загружен файл.

В общий объём входят:

- вложения личных сообщений;
- документы и фото/видео профиля преподавателя;
- материалы онлайн-класса;
- файлы задания преподавателя и попыток ученика;
- подтверждающие файлы в спорах по урокам;
- файлы личной библиотеки и авторские публикации преподавателя.

Материалы с владельцем `PLATFORM`, загруженные самой платформой GoStudy, в
личную квоту технического создателя не входят. Назначение пользователю уже
существующего материала не создаёт копию файла и также не расходует его
хранилище. Внешние ссылки не учитываются, поскольку файл на сервер GoStudy не
загружается.

Ограничения размера одного файла, одной загрузки и одного урока продолжают
действовать дополнительно к общей квоте.

## Конфигурация

```dotenv
UPLOAD_USER_QUOTA_BYTES=314572800
```

Значение по умолчанию — 300 МиБ на аккаунт. Допустимый диапазон конфигурации:
от 10 МиБ до 1 ТиБ. Поле `limit_bytes` в таблице
`user_storage_usages` зарезервировано для будущего индивидуального лимита,
но платные тарифы и приём платежей этим этапом не подключаются.

## Модель и целостность

Миграция `20260924090000_user_storage_quota` создаёт таблицу
`user_storage_usages` и вычисляет исходный `used_bytes` по всем существующим
файловым записям. Она не перемещает и не удаляет файлы.

Корректирующая миграция
`20260924210000_exclude_platform_materials_from_user_quota` пересчитывает
счётчики и исключает материалы GoStudy с владельцем `PLATFORM`. Индивидуальные
лимиты пользователей при перерасчёте сохраняются.

Перед физической записью файла сервер атомарно резервирует его размер в
PostgreSQL. Параллельные загрузки одного аккаунта не могут вместе превысить
лимит. Если запись на диск или сохранение основной сущности завершается
ошибкой, файл и резерв освобождаются. При штатном удалении основная запись и
уменьшение счётчика выполняются одной транзакцией.

## API

Защищённый маршрут:

```http
GET /api/v1/storage/usage
X-Auth-Token: SESSION_TOKEN
```

Пример ответа:

```json
{
  "success": true,
  "used_bytes": 15728640,
  "limit_bytes": 314572800,
  "remaining_bytes": 298844160,
  "usage_percent": 5
}
```

Подробный экран использует отдельный маршрут чтения:

```http
GET /api/v1/storage/overview
X-Auth-Token: SESSION_TOKEN
```

Ответ содержит те же итоговые значения, массив `categories` с объёмом и
количеством файлов по разделам, а также `largest_files` — не более десяти самых
крупных файлов пользователя. Приватные пути файлов API не раскрывает.

`StorageInventoryService` отвечает только за безопасный реестр и навигационные
идентификаторы. Он не удаляет записи других модулей. Экран ведёт пользователя в
профиль, документы, сообщения, домашние задания или личные материалы. Для файла
класса экран вызывает существующую операцию `ClassroomModule`; правила доступа и само
удаление остаются в модуле-владельце.

Удаление также остаётся ответственностью модуля-владельца:

- фото, видеовизитка и документы удаляются существующими профильными
  операциями;
- собственный файл класса преподаватель может удалить прямо из хранилища,
  в том числе после завершения урока; ученик теряет доступ к файлу, но запись урока
  сохраняется;
- личный материал можно удалить после снятия с публикации и отмены активных
  назначений ученикам;
- файлы отменённого или проверенного домашнего задания преподаватель может
  удалить, сохранив само задание, оценку и комментарий в учебной истории;
- вложения отправленных сообщений и файлы принятых домашних работ не удаляются
  из экрана хранилища, поскольку доступны другим участникам и являются частью
  истории взаимодействия;
- вложения споров не удаляются отдельно от обращения, поскольку являются
  доказательной частью истории модерации.

Во всех поддержанных сценариях запись и уменьшение `used_bytes` выполняются в
одной транзакции, а физический файл удаляется после её успешного завершения.
Имена старых файлов перед выдачей в реестре проходят ту же нормализацию
кодировки, что и имена в исходных разделах.

React показывает итог, распределение по разделам и крупные файлы во вкладке
`Настройки → Хранилище`. Преподаватель видит все свои файловые разделы, ученик —
сообщения, ответы на задания и вложения споров, родитель — отправленные им
вложения сообщений и споров.

## Установка

После замены файлов выполнить генерацию Prisma Client и применить миграцию:

```powershell
npm run server:prisma:generate
npm --prefix server run prisma:migrate:deploy
npm --prefix server run prisma:status
```

Затем проверить frontend, backend и граф NestJS-модулей обычными командами
проекта.
