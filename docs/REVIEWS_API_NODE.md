# GoStudy — отзывы на Node/NestJS

Дата: 2 сентября 2026 года.

## Назначение

Модуль обслуживает полный жизненный цикл отзыва: отправку учеником, модерацию,
публикацию, ответ преподавателя, повторную модерацию ответа и пересчёт рейтинга.
React больше не обращается к старым PHP-маршрутам отзывов.

## Бизнес-правила

- отзыв доступен только ученику с активной или архивной учебной связью;
- по этой связи должен существовать хотя бы один урок со статусом `COMPLETED`;
- на связь `ученик — преподаватель — предмет` существует один отзыв;
- оценка — целое число от 1 до 5, текст — от 20 до 3000 символов;
- новый или изменённый отзыв получает статус `PENDING`;
- старая опубликованная версия остаётся видимой до решения по новой редакции;
- рейтинг рассчитывается только по опубликованным оценкам;
- преподаватель отвечает только на опубликованный отзыв;
- ответ публикуется после отдельной модерации;
- при отклонении отзыва или ответа комментарий модератора обязателен;
- удаление опубликованного отзыва преподавателем не предусмотрено.

## Пользовательские маршруты

Маршруты требуют действующий пользовательский токен в `X-Auth-Token`.

| Метод | Маршрут | Роль | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/v1/reviews` | ученик | связи с преподавателями, число проведённых уроков и свой отзыв |
| `GET` | `/api/v1/reviews?page=1&limit=20` | преподаватель | опубликованные отзывы, ответы и сводный рейтинг |
| `POST` | `/api/v1/reviews` | ученик | создать или изменить отзыв и отправить его на модерацию |
| `POST` | `/api/v1/reviews/reply` | преподаватель | отправить ответ на модерацию |

Тело сохранения отзыва:

```json
{
  "relation_id": 4,
  "rating": 5,
  "text": "Очень полезные и понятные занятия."
}
```

Тело ответа преподавателя:

```json
{
  "review_id": 15,
  "text": "Спасибо за отзыв!"
}
```

## Административные маршруты

Доступ разрешён ролям `ADMIN` и `MODERATOR` с действующим административным
токеном.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/admin/reviews` | очередь с поиском, фильтрами и пагинацией |
| `PATCH` | `/api/v1/admin/reviews/:id/moderation` | одобрение или отклонение отзыва либо ответа |

Параметры списка: `page`, `limit`, `q`, `status` и `target`. Значения статуса:
`pending`, `approved`, `rejected`; цели: `review`, `reply` или пустое значение.

Пример решения:

```json
{
  "target": "review",
  "decision": "approved",
  "comment": ""
}
```

Для отклонения используется `decision: "rejected"` и непустой `comment`.
Каждое решение записывается в `admin_audit_logs`.

## База данных

Миграция `20260902200000_reviews` создаёт таблицу `reviews`, статусы модерации,
индексы и внешние ключи, а также добавляет в `teacher_profiles` поля `rating` и
`reviews_count`.

После получения файлов из корня проекта выполнить:

```powershell
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
npm run server:dev
```

Во втором терминале запустить или перезапустить frontend:

```powershell
npm run dev
```

## Проверка полного цикла

1. Убедиться, что ученик и преподаватель связаны по предмету.
2. Преподавателем завершить хотя бы один их урок в интерфейсе класса. Запрос
   `POST /api/v1/classroom/finish` присвоит уроку статус `COMPLETED`.
3. Учеником открыть «Мои преподаватели» и отправить отзыв.
4. В `/admin/reviews` одобрить отзыв.
5. Проверить уведомления обеих сторон, рейтинг и опубликованный отзыв.
6. Преподавателем отправить ответ и одобрить его в админке.
7. Изменить опубликованный отзыв и проверить, что до новой модерации публично
   остаётся предыдущая версия.

Ручное изменение статуса урока в PostgreSQL не требуется: завершение урока и
разблокировка формы отзыва выполняются сервером класса одной транзакцией.
