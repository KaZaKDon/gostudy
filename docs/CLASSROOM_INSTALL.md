# GoStudy — установка хостинговой основы «Класса»

## Что реализовано

- реальная загрузка урока по `/classroom/:lessonId` без данных из навигации;
- строгий доступ только преподавателя и ученика конкретного урока;
- вход открывается за 15 минут до начала;
- урок вручную запускает преподаватель;
- состояния комнаты: `waiting`, `active`, `ended`;
- присутствие участников обновляется без WebSocket обычными API-запросами;
- отдельный сохраняемый чат конкретного урока;
- личная заметка преподавателя сохраняется в черновик журнала;
- защищённые материалы урока загружает только преподаватель;
- файлы хранятся в существующем `UPLOAD_PRIVATE_DIR`;
- изображения, PDF, DOCX и текстовые файлы открываются прямо в рабочей
  области класса; остальные форматы остаются доступными для скачивания;
- преподаватель включает общий показ материала, а ученик получает выбранный
  файл и страницу PDF без перезагрузки;
- ученик может временно выйти из общего показа и вернуться к нему;
- после завершения преподаватель переходит в существующий журнал или
  выдаёт ДЗ через существующий модуль домашних работ;
- видео, демонстрация экрана и совместная доска оставлены независимыми
  будущими адаптерами и не блокируют работу класса.

## 1. База данных

Перед изменением сделать резервную копию рабочей базы.

В phpMyAdmin выполнить:

`docs/database/migrations/2026-07-20_classroom_core.sql`

Затем выполнить:

`docs/database/migrations/2026-07-21_classroom_shared_material.sql`

Будут созданы таблицы:

- `lesson_sessions` — состояние, время и присутствие участников;
- `lesson_messages` — переписка внутри конкретного урока;
- `lesson_files` — закрытые материалы конкретного урока.
- `lesson_workspace_state` — текущий общий материал и страница PDF.

Таблица `lessons` не изменяется. Её рабочие статусы расписания остаются
отдельными от технического состояния комнаты.

## 2. `.env` на хосте

Основа использует уже настроенный абсолютный путь `UPLOAD_PRIVATE_DIR`.

В существующий `.env` рекомендуется добавить:

```dotenv
UPLOAD_CLASSROOM_MAX_BYTES=10485760
UPLOAD_CLASSROOM_TOTAL_MAX_BYTES=31457280
UPLOAD_CLASSROOM_LESSON_MAX_BYTES=104857600
```

- `UPLOAD_CLASSROOM_MAX_BYTES` — размер одного файла, по умолчанию 10 МБ;
- `UPLOAD_CLASSROOM_TOTAL_MAX_BYTES` — размер одного запроса, 30 МБ;
- `UPLOAD_CLASSROOM_LESSON_MAX_BYTES` — общий объём материалов урока,
  100 МБ.

Если строки не добавить, API использует эти же безопасные значения по
умолчанию. `UPLOAD_PRIVATE_DIR` обязателен и должен быть доступен PHP для
записи.

- `/api/lessons/schedule.php`

## 4. Локальный фронтенд

Файлы из комплекта `LOCAL_FRONTEND` размещаются в тех же путях проекта.

После замены `package.json` и `package-lock.json` установить зависимости
локальных просмотрщиков PDF и DOCX:

```bash
npm install
```

После копирования выполнить:

```bash
npm run lint
npm run build
```

## 5. Порядок проверки

1. Назначить урок на ближайшее время.
2. Раньше чем за 15 минут кнопка входа должна быть заблокирована.
3. В разрешённое время войти учеником — отображается ожидание учителя.
4. Войти преподавателем и нажать «Начать урок».
5. У обоих участников должен появиться статус присутствия.
6. Передать несколько сообщений — они появляются без перезагрузки страницы.
7. Преподавателем сохранить личную заметку.
8. Загрузить изображение, PDF, DOCX или TXT и открыть его внутри класса у
   обоих участников.
9. Преподавателем нажать «Показать ученику» — материал должен автоматически
   появиться у ученика.
10. Переключить страницу PDF преподавателем и проверить её смену у ученика.
11. Учеником открыть другой материал, затем нажать «Вернуться к показу
    преподавателя».
12. Остановить показ и скачать файл с обоих аккаунтов.
13. Убедиться, что у ученика нет кнопок загрузки и удаления файла.
14. Завершить урок преподавателем — у ученика состояние изменится автоматически.
15. Перейти в журнал: урок и сохранённая заметка должны быть открыты.
16. Выдать ДЗ: ученик, предмет и урок должны быть выбраны автоматически.
17. Проверить расписание и дневник после публикации результата.

## 6. Что сознательно не входит в этот этап

- видеосвязь;
- аудиосвязь;
- демонстрация экрана;
- синхронная доска;
- продажа материалов;
- платежи.

Эти функции подключаются отдельными модулями и не требуют переделки
созданной основы класса.
