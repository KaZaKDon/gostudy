# Установка этапа «Сообщения»

Архив содержит только новые и изменённые файлы этапа. Его нужно распаковать с
заменой файлов прямо в корень `E:\Project\gostudy`, сохранив структуру папок.

## Команды

Остановить работающий Node API, затем в PowerShell:

```powershell
cd E:\Project\gostudy
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
npm run server:dev
```

Миграция `20260903220000_messages` уже находится в архиве. Если Prisma
предлагает ввести имя ещё одной миграции, нужно отменить команду через
`Ctrl+C` и проверить, что архив распакован именно в корень проекта, а файл
`server\prisma\migrations\20260903220000_messages\migration.sql` существует.

В отдельном терминале перезапустить frontend:

```powershell
cd E:\Project\gostudy
npm run dev
```

## Что проверить

1. Ученик видит принятого преподавателя в разделе «Сообщения».
2. Ученик отправляет текст и файл.
3. У преподавателя появляется красный счётчик в меню и уведомление в
   колокольчике.
4. Преподаватель открывает диалог, скачивает файл и отвечает.
5. Ученик может пожаловаться на входящее сообщение.
6. Жалоба появляется в `/admin/messages`.
7. После перевода учебной связи в архив история остаётся, но отправка
   блокируется.

## Важно

- На локальном компьютере файлы сохраняются в `server\storage\private`.
- На VPS `UPLOAD_PRIVATE_DIR` должен указывать на закрытый каталог вне
  публичной папки сайта.
- Родительский канал уже предусмотрен в базе и API, однако отдельная
  регистрация и кабинет родителя будут подключены следующим самостоятельным
  этапом.
