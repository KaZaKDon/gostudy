# GoStudy — Accounts API админки на Node/NestJS

Дата: 3 сентября 2026 года.

## Назначение

Модуль управляет техническим реестром учётных записей GoStudy. Он не заменяет
анкеты ученика и преподавателя и не предназначен для произвольного
редактирования их персональных данных.

## Маршруты

Все маршруты требуют действующий административный токен.

| Метод | Маршрут | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/v1/admin/accounts` | администратор, модератор | список, поиск, фильтры и пагинация |
| `GET` | `/api/v1/admin/accounts/:id` | администратор, модератор | карточка и счётчики заявок, уроков и домашних заданий |
| `PATCH` | `/api/v1/admin/accounts/:id/status` | только администратор | блокировка, архивирование и восстановление |
| `PATCH` | `/api/v1/admin/accounts/:id/role` | только администратор | смена роли |

## Поиск и фильтры

`GET /api/v1/admin/accounts` принимает:

* `page` — страница от 1;
* `limit` — от 1 до 100, по умолчанию 20;
* `q` — ID, ФИО, email или телефон;
* `role` — `student`, `teacher`, `parent`, `moderator`, `admin`;
* `status` — `active`, `blocked`, `archived`, `deleted`.

## Статусы

Интерфейс администратора изменяет только три состояния:

* `ACTIVE` — аккаунт доступен;
* `BLOCKED` — вход запрещён, обязательна причина блокировки;
* `ARCHIVED` — аккаунт выведен из активной работы без удаления данных.

`DELETED` зарезервирован для отдельной юридической процедуры удаления данных и
не назначается кнопкой «В архив».

При блокировке, архивировании или смене роли все действующие сеансы выбранного
пользователя удаляются. После восстановления пользователь входит заново.

## Защита действий

* модератор может просматривать аккаунты, но не изменять их;
* администратор не может изменить собственную роль;
* администратор не может заблокировать или архивировать собственный аккаунт;
* при переводе в `STUDENT` или `TEACHER` сервер создаёт отсутствующий профиль;
* физическое удаление из раздела Accounts запрещено;
* смена роли и статуса записывается в `admin_audit_logs` вместе с прежним и
  новым значением, администратором, временем, IP и User-Agent.

## Изменения базы данных

Миграция `20260901214500_admin_accounts` добавляет:

* `users.blocked_reason`;
* `users.archived_at`;
* `users.archived_by`;
* `users.archive_reason`;
* таблицу `admin_audit_logs` и необходимые индексы.

После получения файлов выполнить из корня проекта:

```powershell
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
```

Затем перезапустить Node API. Устанавливать новые npm-пакеты не требуется.
