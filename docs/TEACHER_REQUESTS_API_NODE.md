# GoStudy — поиск преподавателя и заявки

**Дата актуализации:** 23 сентября 2026 года  
**Статус:** рабочая цепочка подключена к Node API

## Реализовано

- поиск опубликованных и подтверждённых преподавателей;
- просмотр публичной анкеты, предметов, цен и образования;
- отправка учеником заявки по выбранному предмету;
- отправка родителем заявки за подтверждённого привязанного ребёнка младше
  18 лет;
- защита от повторной активной связи и дублирования ожидающей заявки;
- список активных учеников, архива и новых заявок у преподавателя;
- принятие и отклонение заявки;
- создание или восстановление связи
  `преподаватель–ученик–предмет` при принятии;
- завершение и возобновление обучения;
- основные вкладки карточки ученика: обзор, занятия, родители;
- раздел «Мои преподаватели» у ученика;
- изменение видимости анкеты через Node API.
- уведомление преподавателя о новой заявке и ученика о результате;
- число ожидающих заявок рядом с разделом «Мои ученики».
- увеличенные фотографии в рейтинге и подробной публичной анкете;
- отдельный интерфейсный блок `ПРОДВИЖЕНИЕ` максимум для трёх карточек.
- расширенные фильтры по направлению подготовки, возрасту ученика, городу,
  минимальному стажу, максимальной цене и минимальному рейтингу.

## Карточки продвижения

Ответ `GET /api/v1/teachers` содержит поле `promoted_teachers`. Элементы имеют
тот же публичный формат, что и карточки в `teachers`, поэтому открывают ту же
подробную анкету без отдельного маршрута.

Интерфейс выводит не более трёх карточек в отдельном блоке `ПРОДВИЖЕНИЕ` над
обычным рейтингом. Вся карточка кликабельна и доступна с клавиатуры; отдельной
кнопки «Подробнее» в ней нет. Показываются фотография, фамилия и имя, предмет,
рейтинг и количество отзывов.

Пока платная активация не подключена, API возвращает пустой массив, а пустой
блок не занимает место на странице. Оплата в этот этап не входит. При будущем
подключении продвижение не должно изменять честное место преподавателя в
обычном рейтинге.

## Модульная структура каталога

Публичный каталог отделён от операций с заявками:

- `TeacherDirectoryService` загружает список, рейтинг, пагинацию и подробную
  публичную анкету;
- `TeachersService` отвечает только за отправку заявки преподавателю;
- `TeacherApplicantAccessService` централизованно проверяет роли ученика и
  родителя, а также текущий доступ родителя к несовершеннолетнему ребёнку;
- `teacher-public-profile.mapper.ts` формирует единый публичный контракт
  карточки. Этот же преобразователь предназначен для обычной выдачи и будущих
  карточек продвижения.

Маршруты и формат ответа после разделения не изменились. Миграция базы данных
не требуется.

## Фильтры каталога

`GET /api/v1/teachers` принимает независимые параметры, которые можно
комбинировать:

| Параметр | Назначение |
| --- | --- |
| `search` | ФИО, заголовок анкеты, предмет или направление подготовки |
| `subject_id` | Предмет |
| `preparation_id` | Направление подготовки; вместе с предметом проверяется точная связь |
| `age_group_id` | Возрастная группа ученика |
| `city` | Город без учёта регистра и внешних пробелов |
| `min_experience` | Минимальный стаж в полных годах |
| `max_price` | Максимальная минимальная цена занятия в рублях |
| `min_rating` | Минимальный рейтинг от 0 до 5 с точностью до одного знака |
| `accessible_only=true` | Только анкеты со свободным местом по программе |
| `page` | Страница выдачи по 12 карточек |

Справочники для интерфейса возвращаются в `filters`: `subjects`,
`preparations`, `age_groups` и `cities`. У направления есть `subject_ids`,
поэтому интерфейс показывает только подходящие направления после выбора
предмета.

Рейтинг рассчитывается для полного опубликованного каталога (или для полного
набора выбранного предмета), а остальные фильтры применяются после расчёта.
Поэтому сужение выдачи не присваивает преподавателю искусственно улучшенное
место. Платное продвижение также не участвует в обычном рейтинге.

## Маршруты

```text
GET  /api/v1/teachers
GET  /api/v1/teachers/details?teacher_id=ID
POST /api/v1/teachers/requests
GET  /api/v1/teacher/students
POST /api/v1/teacher/student-requests/respond
POST /api/v1/teacher/students/status
GET  /api/v1/teacher/student-details
GET  /api/v1/student/teachers
POST /api/v1/profile/teacher/visibility
```

Для роли `PARENT` маршруты карточки и отправки заявки принимают
`student_id`. Сервер проверяет его через единую политику родительского доступа:
подтверждённую неархивную карточку, активную подтверждённую связь и точный
возраст младше 18 лет. После прекращения доступа родитель не может просматривать
состояние учебной связи или отправлять новую заявку от имени этого ученика.

## Проверка локально

До появления Node-админки подтверждение преподавателя для локального теста
выполняется в pgAdmin. В запросе заменить email на адрес тестового
преподавателя:

```sql
UPDATE teacher_profiles
SET verification_status = 'VERIFIED',
    is_visible = true,
    updated_at = CURRENT_TIMESTAMP
WHERE user_id = (
    SELECT id
    FROM users
    WHERE email = 'teacher@example.com'
      AND role = 'TEACHER'
);
```

Это только локальный способ проверки разработки. На рабочем сервере статус
выдаёт модератор через будущую админку.

Затем:

1. войти учеником и открыть «Найти преподавателя»;
2. выбрать предмет и отправить заявку;
3. войти преподавателем, открыть «Мои ученики» → «Заявки»;
4. принять заявку;
5. открыть расписание и назначить урок.

После применения миграции уведомлений новая заявка отображается на
колокольчике и увеличивает счётчик раздела. Уже обработанные до обновления
заявки задним числом в ленту не добавляются.
