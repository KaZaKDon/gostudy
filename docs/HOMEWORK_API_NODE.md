# GoStudy — домашние задания на Node/NestJS

Дата: 3 сентября 2026 года.

## Назначение

Модуль `homework` обеспечивает полный цикл задания: преподаватель выдаёт его
ученику, ученик отправляет одну или несколько последовательных попыток,
преподаватель принимает работу либо возвращает её на доработку. Задания можно
связать с конкретным уроком, после чего они отображаются в классе, журнале и
дневнике.

## Маршруты

Все маршруты требуют действующий `X-Auth-Token`.

| Метод | Маршрут | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/v1/homework` | ученик, преподаватель | список и число заданий, требующих действия |
| `GET` | `/api/v1/homework/show?id=ID` | участники задания | полная карточка и история попыток |
| `GET` | `/api/v1/homework/options` | преподаватель | активные связи, уроки и лимиты файлов |
| `POST` | `/api/v1/homework` | преподаватель | выдать задание, `multipart/form-data` |
| `POST` | `/api/v1/homework/submit` | ученик | отправить новую попытку, `multipart/form-data` |
| `POST` | `/api/v1/homework/review` | преподаватель | принять или вернуть последнюю попытку |
| `POST` | `/api/v1/homework/cancel` | преподаватель | отменить задание без попыток |
| `POST` | `/api/v1/homework/viewed` | ученик | зафиксировать первое открытие |
| `GET` | `/api/v1/homework/download?type=assignment&id=ID` | участники задания | защищённо скачать материал задания |
| `GET` | `/api/v1/homework/download?type=submission&id=ID` | участники задания | защищённо скачать файл попытки |

## Бизнес-правила

- выдать задание может только преподаватель из активной учебной связи;
- при привязке к уроку совпадают преподаватель, ученик и предмет;
- необязательный срок сдачи задаётся в часовом поясе преподавателя и должен
  быть не раньше чем через 24 часа;
- ученик отправляет текст, файлы либо оба варианта;
- отправленная попытка неизменяема и ожидает проверки;
- новую попытку можно создать только после возврата предыдущей на доработку;
- возврат на доработку требует комментария;
- принятие попытки закрывает задание как выполненное;
- отменить можно только активное задание, по которому ещё не было попыток;
- карточку и файлы видят только указанные в задании ученик и преподаватель;
- создание, отправка, проверка и отмена формируют внутренние уведомления;
- открытие карточки помечает связанные уведомления прочитанными.

## Файлы

Разрешены PDF, JPG/JPEG, PNG, WebP, TXT, DOC/DOCX, XLS/XLSX и PPT/PPTX.
Сервер проверяет расширение, MIME, сигнатуру, размер и безопасное имя. По
умолчанию можно приложить до пяти файлов, до 10 МБ каждый и до 30 МБ суммарно.
Общий файловый слой восстанавливает UTF-8-названия, если multipart-парсер
прочитал их как Latin-1/Windows-1252. Нормализация применяется при загрузке,
отображении и скачивании, поэтому корректируются и ранее сохранённые названия
без повторной загрузки файлов.

Файлы сохраняются вне публичного каталога и выдаются только через API:

```dotenv
UPLOAD_PRIVATE_DIR=storage/private
UPLOAD_HOMEWORK_MAX_BYTES=10485760
UPLOAD_HOMEWORK_TOTAL_MAX_BYTES=31457280
```

На VPS `UPLOAD_PRIVATE_DIR` должен быть абсолютным путём на российском сервере,
доступным процессу Node для чтения и записи.

## База данных

Миграция `20260903140000_homework` создаёт:

- `homework`;
- `homework_attachments`;
- `homework_submissions`;
- `homework_submission_attachments`;
- статусы задания и попытки, внешние ключи и индексы.

Файлы не хранятся в PostgreSQL: база содержит только закрытый относительный
путь и проверенные метаданные.

## Установка

После замены файлов выполнить из корня проекта:

```powershell
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
npm run server:dev
```

Во втором терминале:

```powershell
npm run dev
```

## Проверка полного цикла

1. Войти преподавателем и выдать задание активному ученику.
2. При необходимости связать задание с уроком и приложить файл.
3. Проверить задание в разделе «Домашние работы» и в классе выбранного урока.
4. Войти учеником, открыть задание, скачать материал и отправить решение.
5. Войти преподавателем, вернуть работу с обязательным комментарием.
6. Учеником отправить вторую попытку и убедиться, что первая осталась в истории.
7. Преподавателем принять работу и поставить оценку.
8. Проверить состояние в журнале, дневнике, карточке ученика и админке.
9. Отдельно создать задание без попыток и проверить его отмену.

Настройки email родителю и отдельный аккаунт родителя относятся к будущему
модулю `parents`. Внутренние уведомления полного цикла уже работают.
