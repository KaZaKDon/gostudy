# GoStudy — безопасность аккаунта на NestJS/PostgreSQL

**Дата:** 8 сентября 2026 года  
**Статус:** реализовано и проверено

## Назначение

Модуль переносит пользовательские операции из `auth/security.php` в отдельный
`SecurityService` внутри Node-модуля `auth`. Все маршруты требуют действующий
`X-Auth-Token` или Bearer-токен.

## Маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/auth/security` | количество активных сеансов текущего пользователя |
| `POST` | `/api/v1/auth/security` | смена пароля или завершение остальных сеансов |

### Получить активные сеансы

Ответ:

```json
{
  "success": true,
  "active_sessions": 2
}
```

В счётчик входят только сеансы с `expires_at` в будущем.

### Завершить остальные сеансы

Запрос:

```json
{
  "action": "logout_other_sessions"
}
```

Текущий сеанс сохраняется, остальные сеансы пользователя удаляются.

### Изменить пароль

Запрос:

```json
{
  "action": "change_password",
  "current_password": "старый пароль",
  "new_password": "новый пароль",
  "new_password_confirmation": "новый пароль"
}
```

Сервер проверяет текущий пароль, требует минимум 8 символов, ограничивает
новый пароль 72 байтами UTF-8, проверяет совпадение подтверждения и не
позволяет повторно установить текущий пароль. После успешной смены пароля
остается только текущий сеанс.

Успешный ответ:

```json
{
  "success": true,
  "message": "Пароль изменён. Остальные сеансы завершены",
  "active_sessions": 1
}
```

Новая миграция базы данных не требуется: используются существующие `users` и
`auth_sessions`. Пароли хранятся через bcrypt, токены сеансов — только в виде
SHA-256-хеша.
