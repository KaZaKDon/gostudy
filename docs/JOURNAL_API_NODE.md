# GoStudy — журнал и дневник на Node/NestJS

Дата: 3 сентября 2026 года.

## Назначение

Модуль `journal` хранит результат проведённого урока. Преподаватель заполняет
журнал после завершения класса, а ученик получает опубликованную запись в
разделе «Дневник обучения».

## Маршруты

Все маршруты требуют действующий `X-Auth-Token`.

| Метод | Маршрут | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/v1/journal` | преподаватель | ученики, предметы и завершённые уроки |
| `POST` | `/api/v1/journal/result` | преподаватель | публикация или изменение результата урока |
| `GET` | `/api/v1/student/diary` | ученик | опубликованные записи дневника |

## Правила публикации

- запись создаёт только преподаватель, указанный в уроке;
- урок должен иметь статус `COMPLETED`;
- для присутствовавшего или опоздавшего ученика результат занятия обязателен;
- отсутствующему ученику нельзя поставить оценку;
- допустимы оценки `2`, `3`, `4`, `5`, `Зачёт` или отсутствие оценки;
- результат, комментарий и личная заметка ограничены 5000 символами каждый;
- первая запись и последующие изменения выполняются через один `upsert`;
- публикация создаёт ученику уведомление, изменение обновляет его.

## Приватность

Поле `teacher_note` возвращается только преподавателю. Ученический маршрут не
включает это поле ни в список, ни в карточку выбранного урока. Ученик видит:

- посещаемость;
- оценку;
- результат занятия;
- комментарий преподавателя;
- тему, предмет, преподавателя и дату урока.

Для каждого урока журнал и дневник также возвращают количество связанных
домашних заданий, ID и название последнего задания, а также состояние
`active`, `expired` или `completed`. Отменённые задания в эту статистику не
включаются.

## Пагинация

История сортируется по дате и ID урока от новых к старым. Размер страницы — 30,
максимум — 50. Для следующей страницы frontend передаёт одновременно:

```text
before_date=YYYY-MM-DD HH:mm:ss
before_id=ID
```

Дата курсора интерпретируется в часовом поясе анкеты пользователя.

## База данных

Используется таблица `lesson_results`, созданная миграцией класса
`20260902213000_classroom`. Новая миграция для журнала не нужна.

Поля записи:

- `attendance`;
- `grade`;
- `lesson_result`;
- `teacher_comment`;
- `teacher_note`;
- `published_at`.

## Проверка полного цикла

1. Провести и завершить урок преподавателем.
2. В завершённом классе нажать «Заполнить журнал».
3. Выбрать посещаемость, оценку и заполнить результат.
4. Добавить комментарий ученику и отдельную личную заметку.
5. Опубликовать запись.
6. Учеником проверить уведомление и раздел «Дневник обучения».
7. Убедиться, что личная заметка ученику не показана.
8. Выдать связанное с уроком задание и проверить его состояние в журнале и
   дневнике.
9. Преподавателем изменить запись и проверить обновление дневника.

После замены файлов достаточно перезапустить API. Если миграция класса ещё не
применена, выполнить:

```powershell
npm run server:prisma:generate
npm run server:prisma:migrate
npm run server:prisma:status
npm run server:dev
```
