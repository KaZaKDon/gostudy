# GoStudy — создание аккаунта ученика родителем

Дата: 8 сентября 2026 года.

## Граница этапа

Родитель создаёт новый аккаунт ученика из подтверждённой администратором
карточки ребёнка. Карточка и аккаунт связываются сразу, так как личность ребёнка
и полномочия представителя уже проверены на предыдущем этапе.

Существующий аккаунт этим маршрутом не присоединяется и не изменяется. Для него
используется отдельный запрос, который должен подтвердить сам ученик.

## Сценарий

1. Родитель открывает подтверждённую карточку ребёнка.
2. Выбирает «Создать новый аккаунт ученика».
3. Указывает новый email, временный пароль и его подтверждение.
4. Сервер одной транзакцией создаёт пользователя `STUDENT`, предварительно
   заполненный профиль и активную связь `parent_students`.
5. На email ученика отправляется стандартное письмо подтверждения.
6. После подтверждения почты ученик входит с временным паролем и завершает свою
   анкету. Данные из карточки уже подставлены.

Пароль по умолчанию скрыт. Каждое из двух полей имеет собственную кнопку-глазок;
переключение видимости не очищает введённое значение.

## Маршрут

- `POST /api/v1/parent/children/:id/create-student-account`

Тело запроса:

```json
{
  "email": "student@example.com",
  "password": "temporary-password",
  "password_confirmation": "temporary-password"
}
```

## Ограничения

- операцию выполняет только владелец карточки с ролью `PARENT`;
- карточка должна быть активна, подтверждена администратором и ещё не связана;
- email не должен принадлежать существующему пользователю;
- пароль содержит от 6 до 72 символов, оба значения должны совпадать;
- новый пользователь обязан подтвердить свой email;
- при создании отменяется ожидающий запрос на привязку по этой карточке;
- сбой отправки письма не отменяет созданный аккаунт: в локальной среде ссылка
  остаётся в журнале API, а отправку можно повторить штатным маршрутом.

## Данные и согласие

Имя, фамилия, город, часовой пояс, год рождения и класс переносятся из карточки
в профиль ученика. Контакты родителя сохраняются как контакт законного
представителя. Новое согласие от имени ученика автоматически не создаётся:
основанием этапа служит отдельное согласие родителя на обработку данных ребёнка,
сохранённое при создании карточки.

## База данных

Новая миграция для этого этапа не требуется. Используются существующие таблицы
`users`, `student_profiles`, `parent_child_profiles` и `parent_students`, а также
таблица запросов из миграции `20260908203000_parent_student_link_requests`.

## Состояние

Серверный маршрут, форма родителя, немедленная связь и email-подтверждение
реализованы. Следующая ручная проверка: создать аккаунт, подтвердить почту,
войти учеником и закончить его анкету.
