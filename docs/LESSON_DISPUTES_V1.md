# Споры по урокам — версия 1

Дата: 24 сентября 2026 года.

## Назначение

Модуль фиксирует спорную ситуацию по конкретному уроку и передаёт её
администратору или модератору. На первом этапе он не выполняет возвраты,
списания и другие финансовые операции.

Участники:

- преподаватель урока;
- ученик урока;
- подтверждённый родитель несовершеннолетнего ученика;
- администратор или модератор.

## Модульная структура

- `LessonDisputesModule` отвечает за обращения участников, ответы, вложения,
  проверку доступа и пользовательские уведомления;
- `AdminLessonDisputesModule` отвечает за очередь модерации, решения и
  административный аудит;
- `StorageQuotaModule` только учитывает объём загруженных доказательств и
  показывает навигацию к спору;
- `NotificationsModule` доставляет уведомления существующим способом;
- платёжные модули и расчёты уроков не вызываются.

Один урок может иметь только один спор. Повторное обращение по тому же уроку
не создаётся, поэтому переписка и решение остаются в одной истории.

## Жизненный цикл

Статусы обращения:

1. `OPEN` — участник открыл спор.
2. `UNDER_REVIEW` — модератор взял спор в работу.
3. `RESOLVED` — принято решение в пользу одной из сторон либо зафиксировано
   взаимное соглашение.
4. `REJECTED` — нарушение не подтверждено.

После `RESOLVED` или `REJECTED` участники не могут добавлять ответы. Все
переходы сохраняются в `lesson_dispute_events`, а действия модератора — также
в `admin_audit_logs`.

## Когда можно открыть спор

Обращение доступно после завершения или отмены урока. Для урока, который всё
ещё имеет статус `SCHEDULED`, сервер проверяет расчётное время окончания по
дате начала и продолжительности. Активный урок и активная сессия всегда
исключаются.

Доступ проверяется по самому уроку. Родитель получает доступ только к текущему
подтверждённому несовершеннолетнему ребёнку.

## Причины и решения

Причины участника:

- неявка;
- поздняя отмена;
- урок не состоялся;
- проблема с проведением урока;
- другая проблема.

Решения модератора:

- заявитель прав;
- вторая сторона права;
- взаимное соглашение;
- нарушение не подтверждено.

Обоснование решения обязательно и должно содержать не менее 10 символов.

## Вложения и хранилище

К первоначальному обращению и каждому ответу можно приложить до пяти файлов.
По умолчанию один файл ограничен 10 МиБ, одна отправка — 30 МиБ. Настройки:

```dotenv
UPLOAD_DISPUTE_MAX_BYTES=10485760
UPLOAD_DISPUTE_TOTAL_MAX_BYTES=31457280
```

Файлы хранятся приватно, выдаются только после проверки доступа и учитываются
в личной квоте загрузившего аккаунта. Вложения являются частью истории
модерации и отдельно из экрана хранилища не удаляются.

## API участников

Все маршруты требуют обычную пользовательскую сессию:

```http
GET  /api/v1/lesson-disputes
GET  /api/v1/lesson-disputes/options
GET  /api/v1/lesson-disputes/:id
POST /api/v1/lesson-disputes
POST /api/v1/lesson-disputes/:id/messages
GET  /api/v1/lesson-disputes/:id/attachments/:attachmentId
```

Создание и ответы используют `multipart/form-data`; имя файлового поля —
`files[]`.

## API администрации

Маршруты доступны ролям `ADMIN` и `MODERATOR`:

```http
GET   /api/v1/admin/lesson-disputes
GET   /api/v1/admin/lesson-disputes/:id
PATCH /api/v1/admin/lesson-disputes/:id
GET   /api/v1/admin/lesson-disputes/:id/attachments/:attachmentId
```

Взятие в работу:

```json
{ "action": "review" }
```

Решение:

```json
{
  "action": "decide",
  "decision": "applicant_supported",
  "comment": "Обоснование решения модератора"
}
```

## Интерфейс

В кабинетах преподавателя, ученика и родителя добавлен раздел `Споры`.
Уведомление открывает нужное обращение. В админке очередь доступна по адресу
`/admin/lesson-disputes`.

## Установка

После замены файлов:

```powershell
npm run server:prisma:generate
npm --prefix server run prisma:migrate:deploy
npm --prefix server run prisma:status
```

Миграция `20260924220000_lesson_disputes_v1` создаёт таблицы обращений,
ответов, вложений и событий. Существующие уроки и файлы не изменяются.

Проверки проекта:

```powershell
npm run lint
npm run build
npm run server:lint
npm run server:test
npm --prefix server run test:modules
```
