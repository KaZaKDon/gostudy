# GoStudy — карточка ребёнка в кабинете родителя

Дата: 8 сентября 2026 года.

## Граница этапа

Авторизованный родитель создаёт отдельную карточку несовершеннолетнего ребёнка.
Карточка сохраняется со статусом `PENDING` и ещё не является ученическим
аккаунтом: для ребёнка не создаются фиктивные email или пароль, не открывается
вход и не формируется рабочая связь `parent_students`.

Активация ученика и связывание аккаунтов выполняются следующим отдельным
этапом после административного подтверждения карточки.

## Маршруты

Оба маршрута требуют действующий сеанс пользователя с ролью `PARENT`.

- `GET /api/v1/parent/children` — карточки детей текущего родителя;
- `POST /api/v1/parent/children` — создание карточки.

Пример запроса:

```json
{
  "last_name": "Иванов",
  "first_name": "Алексей",
  "middle_name": "Петрович",
  "birth_date": "2013-04-12",
  "city": "Москва",
  "timezone": "Europe/Moscow",
  "class_level": "6 класс",
  "representative_type": "parent",
  "legal_acceptance": {
    "accepted": true
  }
}
```

`representative_type` принимает `parent`, `guardian` или `trustee`.

## Проверки и хранение

- дата рождения должна быть корректной, прошедшей и соответствовать возрасту
  младше 18 лет;
- согласие на обработку данных конкретного ребёнка обязательно и фиксируется
  отдельно от регистрационных согласий родителя;
- сервер сохраняет текст согласия, версии и SHA-256 документов, IP и User-Agent;
- повторная активная карточка ребёнка с теми же именем, фамилией и датой рождения
  у одного родителя отклоняется;
- полная дата рождения доступна только авторизованному родителю и серверным
  административным сценариям;
- новая карточка получает статус `PENDING`.

## Интерфейс

В разделе родителя «Мои дети» доступны список карточек и форма добавления.
Форма не запрашивает email или пароль ребёнка. После сохранения карточка
показывает статус проверки и признак создания ученического аккаунта.

## Административная проверка

Маршруты требуют роль `ADMIN`; модератор юридическую связь не подтверждает.

- `GET /api/v1/admin/parent-children` — очередь с поиском, статусом и
  пагинацией;
- `PATCH /api/v1/admin/parent-children/:id/review` — решение по карточке.

Решения: `approved`, `needs_clarification`, `rejected`. Для запроса уточнений и
отклонения комментарий обязателен. Решение сохраняется в журнале действий с IP
и User-Agent, а родитель получает внутреннее уведомление. Новая миграция для
административной проверки не требуется.

## Связь с аккаунтом ученика

Привязка существующего аккаунта и создание нового аккаунта ученика из
подтверждённой карточки реализованы отдельным модулем. Новый аккаунт связывается
сразу; существующему аккаунту требуется подтверждение самого ученика.

Принятое правило сообщений: родитель использует собственный отдельный чат с
преподавателем и также имеет доступ на чтение к переписке ребёнка с
преподавателем и вложениям. От имени ребёнка родитель не пишет.
