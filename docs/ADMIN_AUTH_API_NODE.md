# GoStudy — авторизация админки на Node/NestJS

Дата: 1 сентября 2026 года.

## Что реализовано

Административная авторизация больше не использует PHP-сессию. React и NestJS
работают через непрозрачный токен, а в PostgreSQL хранится только его SHA-256.
Токен админки отделён от пользовательского токена и сохраняется в
`sessionStorage` под ключом `gostudy_admin_token`.

Доступ разрешён только активным пользователям с подтверждённой почтой и ролью
`ADMIN` или `MODERATOR`.

## Маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/v1/admin/auth/login` | проверить email, пароль, статус и административную роль; создать сессию |
| `GET` | `/api/v1/admin/auth/me` | проверить токен и вернуть текущего администратора |
| `POST` | `/api/v1/admin/auth/logout` | удалить текущую сессию |

Для `me` и `logout` frontend отправляет токен в заголовке
`X-Auth-Token`. Также сервер поддерживает `Authorization: Bearer <token>`.

## Требования к учётной записи

В таблице `users` должны быть:

* `role = 'ADMIN'` или `role = 'MODERATOR'`;
* `status = 'ACTIVE'`;
* заполненное `email_verified_at`;
* bcrypt-хеш пароля в `password_hash`.

Проверить административные аккаунты можно в `psql`:

```sql
SELECT
    id,
    email,
    role,
    status,
    email_verified_at
FROM users
WHERE role IN ('ADMIN', 'MODERATOR')
ORDER BY id;
```

Если уже зарегистрированный и подтверждённый аккаунт нужно назначить
администратором, роль меняют отдельной командой после проверки точного email:

```sql
UPDATE users
SET
    role = 'ADMIN',
    profile_completed = true,
    updated_at = CURRENT_TIMESTAMP
WHERE email = 'admin@example.com';
```

Перед выполнением замените `admin@example.com` на фактический адрес и сначала
проверьте выбранную запись через `SELECT`.

## Проверка локально

1. Запустить PostgreSQL.
2. Запустить API: `npm run server:dev`.
3. Запустить frontend: `npm run dev`.
4. Открыть `/admin/login`.
5. Войти учётной записью с ролью `ADMIN` или `MODERATOR`.
6. Обновить страницу `/admin/dashboard`: защищённая сессия должна сохраниться.
7. Нажать «Выйти»: токен удаляется на сервере и в браузере.

## Текущая граница миграции

Контур `login / me / logout`, Dashboard, разделы «Аккаунты», «Преподаватели»,
«Ученики», «Отзывы» и административные справочники уже работают только через
Node. Остальные операционные разделы переносятся отдельными модулями.
