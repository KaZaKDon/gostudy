# GoStudy — уведомления в Node API

**Дата:** 20 сентября 2026 года  
**Статус:** лента, колокольчик, счётчики, события детей и настройки подключены к Node API

## Реализовано

- хранение уведомлений в PostgreSQL;
- число непрочитанных уведомлений на колокольчике;
- число ожидающих заявок рядом с разделом «Мои ученики»;
- переход из уведомления о заявке сразу на вкладку «Заявки»;
- переход из уведомления о назначенном уроке в расписание на нужную дату;
- отметка одного или всех уведомлений прочитанными;
- удаление одного уведомления и очистка прочитанных либо всей ленты;
- чтение и сохранение настройки писем родителю из кабинета ученика без legacy
  PHP;
- обновление ленты каждые 15 секунд, при возврате на вкладку браузера и после
  обработки заявки.

## События

| Событие | Получатель | Результат |
| --- | --- | --- |
| Ученик отправил заявку | Преподаватель | Уведомление и увеличение счётчика заявок |
| Преподаватель принял заявку | Ученик | Уведомление о принятии |
| Преподаватель отклонил заявку | Ученик | Уведомление об отклонении |
| Преподаватель назначил урок | Ученик | Уведомление со ссылкой на дату в расписании |
| Участник предложил перенос или отмену | Второй участник | Уведомление со ссылкой на урок |
| Второй участник ответил | Автор предложения | Уведомление о принятии или отклонении |
| Автор отозвал предложение | Второй участник | Уведомление об отзыве |
| Преподаватель выдал или отменил задание | Ученик | Уведомление со ссылкой на задание |
| Ученик отправил новую попытку | Преподаватель | Уведомление о работе на проверке |
| Преподаватель принял или вернул работу | Ученик | Результат проверки и ссылка на задание |
| Выдано, проверено или отменено задание ребёнка | Подтверждённый родитель | Уведомление с именем ребёнка и переходом к заданию |
| Опубликован или обновлён результат ребёнка | Подтверждённый родитель | Уведомление с переходом в дневник нужного ребёнка |
| Согласован перенос или отмена урока ребёнка | Подтверждённый родитель | Уведомление с переходом в расписание нужного ребёнка |
| Преподаватель написал в чат ребёнка или родителя | Подтверждённый родитель | Уведомление с переходом в нужный диалог |

Для каждого события используется ключ дедупликации. Повторный запрос не
создаёт несколько одинаковых уведомлений.

Родительские события создаются только при активной подтверждённой связи,
подтверждённой и неархивной карточке ребёнка и возрасте младше 18 лет.
Для семьи с несколькими детьми прямой переход выбирает ребёнка по целевой
записи, а не по текущему положению переключателя в кабинете.

## Маршруты

```text
GET  /api/v1/notifications?limit=20&before_id=ID
POST /api/v1/notifications/read
POST /api/v1/notifications/delete
POST /api/v1/notifications/clear
GET  /api/v1/notifications/parent-settings
POST /api/v1/notifications/parent-settings
GET  /api/v1/notifications/student-settings
POST /api/v1/notifications/student-settings
```

Ответ списка содержит `unread_count` и
`counters.teacher_requests`. Счётчик заявок вычисляется по фактическим заявкам
со статусом `PENDING`, поэтому удаление уведомления не скрывает саму заявку.

`GET /parent-settings` доступен только родителю и возвращает по одной записи
на каждого активного подтверждённого несовершеннолетнего ребёнка. Если
сохранённой настройки ещё нет, все категории возвращаются включёнными.

Для `POST /parent-settings` передаются обязательные поля:

```json
{
  "student_id": 9,
  "homework_enabled": true,
  "diary_enabled": true,
  "schedule_enabled": false,
  "messages_enabled": true
}
```

Сервер повторно проверяет доступ родителя к указанному ребёнку. Настройка
`messages_enabled` управляет уведомлениями как о новых сообщениях в чате
ребёнка, так и о сообщениях преподавателя в собственном чате родителя.

`GET /student-settings` доступен только ученику и возвращает сохранённый email
родителя и признак `parent_notifications_enabled`. `POST /student-settings`
сохраняет этот признак. Включение невозможно, пока в анкете ученика не указан
email родителя. Маршруты сохраняют настройку будущей email-доставки; сама
отправка событий по email остаётся отдельным этапом.

## Миграция и проверка

Миграция `20260901143000_notifications` добавляет таблицу `notifications`.
Миграция `20260911113000_parent_notification_preferences` добавляет отдельные
настройки категорий для пары родитель–ребёнок. Обе миграции не изменяют
существующие аккаунты, анкеты, заявки или уроки.

Миграция `20260920133000_student_notification_settings_node` добавляет в
профиль ученика признак `parent_notifications_enabled` со значением `false` по
умолчанию. Legacy-маршрут `student/notification-settings.php` больше не
используется frontend.

Уведомления создаются с момента применения миграции и запуска нового API.
Ранее уже обработанные заявки задним числом в ленту не добавляются. Для
быстрой проверки можно назначить новый урок: ученик увидит уведомление не
позднее следующего 15-секундного опроса либо сразу после возврата на вкладку.
