# GoStudy — Robokassa: решения и состояние интеграции

Дата фиксации: 30 октября 2026 года (Москва).
Статус: тестовая интеграция развёрнута; фискализация и реальные платежи ещё не реализованы полностью.
Документ фиксирует решения из рабочего обсуждения, а не подтверждает готовность платёжной системы к промышленной эксплуатации.

## 1. Действующая модель

- GoStudy продаёт преподавателям доступ к функциям программной платформы на 30 дней.
- Единая подписочная модель для преподавателей; прежняя схема комиссии с уроков не применяется в текущей версии.
- Обсуждавшаяся базовая цена: 990 ₽ за 30 дней с двумя активными учениками, дополнительный блок из двух учеников — 400 ₽. Источник фактической цены для оплаты — опубликованная редакция тарифа в БД; значения нельзя жёстко закреплять в платёжном коде.
- Оплата уроков производится напрямую между участниками. Приём оплаты уроков, Split, удержание средств и выплаты преподавателям остаются за пределами текущего этапа.
- Дополнительные места рассматриваются как отдельно оплачиваемое расширение. Расчёт доплаты в середине периода, срок действия расширения и правила его зачёта требуют отдельной реализации и согласования до запуска такого сценария.

## 2. Утверждённые настройки фискализации

| Параметр | Решение |
| --- | --- |
| Решение Robokassa | «Робочеки» |
| Идентификатор магазина | gostudy |
| Метод платежа | Предоплата 100% (`full_prepayment`) |
| Предмет расчёта | Услуга (`service`) |
| СНО | УСН «Доходы» (`usn_income`) |
| НДС | Без НДС (`none`) |
| Телефон | +79515220669 |

СНО и отсутствие НДС подтверждены пользователем со слов бухгалтера. Бухгалтер объяснил порядок: сначала оплата, затем использование в течение периода. После уточнения значений пунктов меню пользователь выбрал «Предоплата 100%».

Основание выбранного метода: весь согласованный объём подписки оплачивается до оказания услуги за период. Возможность позже приобрести дополнительные места сама по себе не превращает первоначальную оплату в частичную.

В терминологии Robokassa:
- `full_prepayment` — полная предоплата;
- `prepayment` — частичная предоплата;
- `advance` — аванс;
- `full_payment` — полный расчёт.

На экране Robokassa указано, что «Робочеки» нельзя использовать с АУСН. Для GoStudy подтверждена обычная УСН «Доходы», а не АУСН.

Фактическое завершение перехода на «Робочеки» в кабинете и получение статуса подключения пока не подтверждены. До перехода пользователь должен ознакомиться с офертой сервиса.

## 3. Номенклатура и два чека

В каждом запросе на настоящий платёж необходимо передавать `Receipt`: название услуги, количество, сумму, налоговую ставку, метод и предмет расчёта. Одного включения «Робочеков» в кабинете недостаточно.

Предлагаемые позиции:
- «Доступ к платформе GoStudy по тарифу [название] на 30 дней»: количество 1, стоимость из опубликованного тарифа;
- при покупке расширения — отдельная позиция «Дополнительный блок из 2 учеников …» с количеством блоков, фактической ценой и ясным сроком предоставления.

Названия должны отражать фактическую покупку; сумма позиций должна совпадать с суммой платежа. Нельзя подменять подписку оплатой образовательной услуги или урока.

Принятая схема требует:
1. Чека предоплаты при успешной оплате.
2. Итогового чека с зачётом предоплаты после оказания услуги за оплаченный период.

Формирование итогового чека не является повторным списанием денег. Автоматизацию второго чека ещё предстоит разработать. Момент его формирования, обработку досрочного прекращения доступа, возвратов и расширений нужно согласовать с бухгалтером и отразить в коде и документах.

Предупреждение о штрафах на экране не копируется как самостоятельное юридическое заключение: размеры и применимость санкций в рамках этой работы не проверялись.

## 5. Настройки теста и точка продолжения

Тестовый преподаватель: ID 3 (`vnukovdn@vk.com`). Другого преподавателя ID 4 в разрешённый список не включать без отдельного решения.

Настройки `/etc/gostudy/app.env`:

```ini
ROBOKASSA_TEST_ENABLED=true
ROBOKASSA_MERCHANT_LOGIN=gostudy
ROBOKASSA_TEST_PASSWORD1=<секрет, не включать в документацию>
ROBOKASSA_TEST_PASSWORD2=<секрет, не включать в документацию>
ROBOKASSA_TEST_TEACHER_IDS=3
```

Пользователь сообщил «готово» после инструкции сохранить настройки. Перезапуск API после этого последнего изменения и проверка доступности тестовой панели ещё не подтверждены.

Адреса, которые должны быть сохранены в кабинете Robokassa:

| Назначение | URL | Метод |
| --- | --- | --- |
| Result | https://gostudyonline.ru/api/v1/payments/robokassa/result | POST |
| Success | https://gostudyonline.ru/api/v1/payments/robokassa/success | GET |
| Fail | https://gostudyonline.ru/api/v1/payments/robokassa/fail | GET |

Для теста используются отдельные тестовые пароли и MD5, согласованный с текущей реализацией. Ранее в форме встречались ошибки вставки URL; окончательное сохранение корректных адресов следует подтвердить при проверке.

Возврат браузера на Success URL сам по себе не означает успешную оплату: статус подтверждает серверное уведомление Result URL.

Секреты не отправлять в чат и не включать в архивы. Не выполнять `source /etc/gostudy/app.env`: это файл окружения systemd, а не shell-скрипт.
